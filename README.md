# تنظيم حضور أعضاء نقابة المبرمجين العراقيين — ITEX 2026

تطبيق مستقل (صفحات ثابتة + دوال Vercel + Upstash Redis) لتنظيم جدول حضور
أعضاء نقابة المبرمجين العراقيين الـ23 في بوث النقابة بمعرض ITEX 2026
(معرض بغداد الدولي)، للأيام: الأربعاء 30/9، الخميس 1/10، الجمعة 2/10،
السبت 3/10 — من الساعة 10:00 صباحاً حتى 8:00 مساءً.

## الفكرة

- كل عضو من الـ23 له **رابط خاص** (بدون كلمة مرور أو حساب) يفتحه من هاتفه
  ويحدد حضوره لكل يوم من الأيام الأربعة: **يوم كامل / صباحي (10-3) /
  مسائي (3-8) / غير متاح**. يمكنه العودة لاحقاً وتعديل اختياره.
- لوحة إدارة محمية بكلمة مرور واحدة (`ADMIN_PASSWORD`) تعرض جدول الجميع
  مصنّفين حسب مناصبهم، وملخصاً يومياً لعدد الحاضرين بكل شفت مع تنبيه
  عند عدم وجود أي تغطية لشفت معيّن.
- قاعدة بيانات واحدة مشتركة (Redis) — كل التحديثات فورية ومرئية للجميع
  من لوحة الإدارة، لا حاجة لتزامن يدوي.
- لا يحتاج بطاقة ائتمان ولا سيرفر تديره بنفسك — Vercel يستضيف الصفحات
  ودوال الـ API مجاناً، بنفس روح صفحة ثابتة بسيطة.

## النشر المجاني على Vercel (رابط مباشر، بدون بطاقة، بدون سيرفر)

1. افتح https://vercel.com/new وسجّل دخول بـ **"Continue with GitHub"**
   (نفس حساب GitHub الذي يملك هذا المستودع — بدون كلمة مرور جديدة، وبدون
   طلب بطاقة ائتمان).
2. اختر مستودع **`itex2026-attendance`** من القائمة واضغط **Import**.
3. Vercel يكتشف المشروع تلقائياً (لا إعدادات build مطلوبة) — اضغط
   **Deploy** مباشرة. خلال دقيقة تقريباً يعطيك رابطاً جاهزاً مثل:
   `https://itex2026-attendance.vercel.app`
4. من صفحة المشروع في Vercel: تبويب **Storage** → **Create Database** →
   اختر **Redis** (من الـ Marketplace، الخطة المجانية) → **Connect to
   Project**. يربط هذا قاعدة البيانات تلقائياً بدون أي نسخ/لصق لروابط
   اتصال.
5. تبويب **Settings → Environment Variables**: أضف متغيّرين فقط:
   - `ADMIN_PASSWORD` = كلمة مرور قوية من اختيارك للوحة الإدارة
   - `SESSION_SECRET` = أي نص عشوائي طويل
6. تبويب **Deployments** → اضغط **Redeploy** على آخر نشر (حتى تُطبَّق
   المتغيرات الجديدة). هذا هو كل شيء — الرابط في الخطوة 3 يعمل الآن
   بكامل ميزاته.

## التشغيل محلياً

```bash
npm install
cp .env.example .env   # عدّل ADMIN_PASSWORD و SESSION_SECRET
npx vercel dev          # أو أي مشغّل محلي يدعم دوال Vercel
```

بدون `vercel dev`، يمكن أيضاً استدعاء الدوال في `api/` مباشرة (كما تفعل
اختبارات المشروع) — الفرق أن هذا لا يقدّم الصفحات الثابتة عبر HTTP.

بدون متغيرات Redis (`KV_REST_API_URL`/`KV_REST_API_TOKEN` أو
`UPSTASH_REDIS_REST_URL`/`UPSTASH_REDIS_REST_TOKEN`) يستخدم التطبيق
تلقائياً ذاكرة مؤقتة داخل العملية — مناسب للتطوير المحلي فقط، وليس
للإنتاج (تُفقد البيانات عند كل إعادة تشغيل).

عند أول طلب لأي مستخدم يتم زرع الأشخاص الـ23 بأسمائهم ومناصبهم كما
وردت بالضبط تلقائياً، كل واحد برابط وصول عشوائي فريد.

## الحصول على روابط الأعضاء

سجّل دخول لوحة الإدارة (`/admin.html`) بكلمة المرور، ومن تبويب "جدول
الأعضاء" اضغط "نسخ الرابط" أمام كل شخص وأرسله له (واتساب مثلاً).
الرابط بالشكل: `https://your-app.vercel.app/?t=<token>`.

## البيئة (متغيرات البيئة)

| المتغير | الوصف |
|---|---|
| `ADMIN_PASSWORD` | كلمة مرور لوحة الإدارة — **غيّرها قبل النشر** |
| `SESSION_SECRET` | سر توقيع جلسة الإدارة — **غيّرها قبل النشر** |
| `KV_REST_API_URL` / `KV_REST_API_TOKEN` | تُضاف تلقائياً عند ربط Redis من Vercel |

## البنية

```
api/attendance.js      نقطة الـ API العامة (بدون تسجيل دخول) — عرض وحفظ حضور شخص واحد عبر رابطه
api/admin.js            نقطة الـ API الإدارية (دخول/خروج/الجدول الكامل/تعديل أي شخص)
lib/rules.js            الأيام الأربعة الثابتة، أنواع الحضور، وأوقاتها — مصدر واحد
lib/roster.js           زرع الأشخاص الـ23 وقراءتهم/حفظهم في القاعدة
lib/store.js            غلاف بسيط فوق Redis (مع بديل ذاكرة مؤقتة محلياً)
lib/session.js          جلسة إدارة موقّعة عبر كوكي، بدون نظام حسابات جديد
index.html              صفحة الشخص (يفتحها برابطه الخاص ?t=TOKEN)
attendance-app.js        منطق صفحة الشخص
admin.html               لوحة الإدارة
admin-app.js             منطق لوحة الإدارة (تسجيل الدخول + الجدول + الملخص)
style.css                التنسيق المشترك (عربي RTL، متجاوب مع الهاتف)
```
